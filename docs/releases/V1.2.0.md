# FieldOps v1.2.0 — Technician Service Records

Release date: October 29, 2026. Implemented browser prototype; owner acceptance pending. Previous product source remains preserved under releases/v1.1.0, with v1.0.0 also retained. The v1.1.0 gallery remains available as historical evidence.

## Changes in this subsequent version

- Technician-centered Home with two sourced/credited repair-work photographs, scheduled visits and emergency attention links.
- Repairs workspace with nine standardized reschedule reasons, requester/recorder, notes, confirmation and original/revised appointments.
- Three fictional repair orders, immutable client links and three fictional service technicians; Toronto scheduling with collision and DST checks.
- Twenty-five technician update types covering diagnostics, performed work, emergencies, urgent replacements, parts, approval, maintenance, follow-up and closure.
- Versioned client-linked work journal retaining findings, work, parts, next action, severity/status, service impact, downtime estimate, proposed extra cost (CAD), recorded notification/authorization and follow-up.
- Complete appointment/issue records in validated JSON backups; concise event summaries in operations history/CSV; staffing reset retains service records.
- Current screenshots, usage guide, asset credits, ADLC, change history and repair/client-impact flowchart.

## Limits and migration

Field-service records are a focused extension of the earlier deterministic staffing/recording prototype, not an already integrated repair company system. Fixed historical delivery metrics do not change when a repair note is recorded. No arbitrary real customer/order creation, attachments, automated messaging, billing, inventory, purchasing or verified client approvals. Browser-local, self-declared identity; no protected shared retention. Existing saves receive clearly simulated starting repair orders and empty issue journals without invented client interactions.
