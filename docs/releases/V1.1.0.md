# FieldOps v1.1.0 — Workflow History & Recovery

Release date: October 29, 2026. Product status: implemented browser prototype; owner acceptance pending. This is the subsequent version of v1.0.0, not a replacement of its historical documentation.

## User requirements

The owner requested an upgrade of FieldOps first, followed later by other applications. Work must have a complete, individually inspectable workflow history rather than only a text log: operator, steps taken, changes, review and rework. The interface must use light gray and violet. Previous/current versions and the ADLC must be documented.

## Implemented behavior

See ../WORKFLOW-HISTORY.md for usage and ../../CHANGELOG.md for the full change list. Work items progress through Assigned → In progress → Submitted → Accepted, Rework or Rejected. Rework passes through execution and submission again. Each event retains operator, timestamp, record/project, action, reason and before/after data. Staffing, QA, incidents and connectivity actions also generate structured events.

Work records and decisions remain when resetting staffing to baseline. Backups include workflow history and are validated before restore. Damaged saved data is preserved. Restore and reset require explicit user actions. Current operator names are editable demo identity, not verified authentication.

## Verification

- Original model assertion suite passed after implementation.

- Browser checks passed for backup download/restore, persisted restore, reset cancellation, operator selection, execution, submission with output reference, review-to-rework, four-step history after reload, and workflow CSV download.
- Light-gray/violet workflow appearance inspected visually.
- Full mobile viewport, real multiuser concurrency, backend identity, durable server retention and production data were not tested or implemented.

## Version and migration policy

`VERSION` and the UI display 1.1.0. Backup format version 1 and workspace schema version 2 are distinct compatibility identifiers. Existing valid saves receive clearly labeled simulated starting work records. Old plain-text actions remain available; no earlier structured user history is fabricated. Returning to v1.0.0 does not guarantee it will understand new fields: export a full v1.1.0 backup before reverting source.
