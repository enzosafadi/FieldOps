# FieldOps — Product Capabilities and Pilot Readiness

Baseline v1.3.0. Evidence reviewed November 1, 2026. A working simulated prototype, with production and customer acceptance still pending.

## Capability status

| Capability | Current evidence | Boundary |
| --- | --- | --- |
| Technician home and service visits | Three fictional orders and three technicians | Real order intake/import and arbitrary customer creation are not implemented |
| Repair rescheduling | Nine reasons, original/revised slots, requester, operator, notes and recorded confirmation | Working hours, routing/travel time, parts availability and real client messaging are not integrated |
| Technician documentation | 25 update categories, work/findings/parts/next action, client-linked versions | No attachments or equipment-manual repository |
| Client ramifications | Service impact, downtime, proposed CAD estimate, recorded notification/approval and follow-up | No invoice totals, purchases, charges or verified signatures |
| Voice assistance | English/French adapter, editable preview, explicit insertion/save and typing fallback | Device microphone/provider acceptance pending; browser may process audio remotely |
| Work-item lifecycle | Controlled stages and retained record history | Separate from fixed historical aggregate delivery metrics |
| Recovery and exports | Validated JSON backup and concise CSV history | Local editable history is not a shared authoritative audit log |
| AI report generation | Requirements and acceptance design only | Grounded generation and retrieval are not implemented |
| Reporting-time measurement | Proposed pilot measures | No timer, baseline or achieved savings |

## Before a real team pilot

| Gate | Required completion evidence |
| --- | --- |
| Buyer workflow | Named sponsor, technicians/dispatch participants, scoped jobs and confirmation of a genuine workflow gap |
| Device acceptance | Real English/French speech tests, noise/vocabulary trials, keyboard fallback and mobile viewport check |
| Identity and data | Authenticated roles, client access controls, shared durable storage, server validation and concurrent-edit handling |
| Operational integration | Approved service-order intake and the buyer's actual schedule/parts/billing boundaries |
| Recovery and operations | Tested backups, restore ownership, retention policy, monitoring and support responsibility |
| Commercial evaluation | Agreed baseline, success measures, pilot duration, implementation/support costs and stop/continue decision |

## Appropriate positioning

FieldOps can be demonstrated as a technician reporting and service-history prototype. A focused pilot or custom module is the next offer to validate with buyers. It is not currently a turnkey production service-management platform. Candidate companies are hypotheses for discovery, not confirmed interested buyers.
